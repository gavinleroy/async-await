\subsection{Translating Pseudocode to Each Language}

The translation from pseudocode to each language is straightforward:

\begin{enumerate}
  \item Function calls translate into function calls
  \item \code|spawn| is translated into a \code|spawn| for runtimes that have it (Asyncio, Trio, Tokio, Smol) and a \emph{noop} for languages that don't (\CSharp, \Js, Swift)
  \item All throwing functions are assumed to have a \code|try| in front of them following Swift semantics
  \item  \code|timeout| translates to the respective implementation of the minimal semantics in \Cref{sec:straightline-async}.
\end{enumerate}

\subsection{Additional Implementations of timeout}
\label{app:timeout-impls}

\textbf{\Js}

\begin{lstlisting}[language=Javascript]
function sleepCancellable(duration: number, opts?: { signal?: AbortSignal }): Promise<null> {
  let timerId: number;
  let signalHandler: () => void;
  const timer = new Promise<null>((accept, reject) => {
    signalHandler = () => reject(opts?.signal?.reason);
    opts?.signal?.addEventListener("abort", signalHandler, { once: true });
    timerId = setTimeout(() => accept(null), duration);
  })

  return timer.finally(() => {
    clearTimeout(timerId);
    opts?.signal?.removeEventListener("abort", signalHandler);
  });
}

async function timeoutCancellable<T>(
  duration: number,
  controller: AbortController,
  f: (signal: AbortSignal) => Promise<T>,
): Promise<T | null> {
  const result = await Promise.race([
    sleepCancellable(duration, { signal: controller.signal }),
    f(controller.signal)
  ]);
  if (result === null) controller.abort();
  return result;
}
\end{lstlisting}

\textbf{Rust+Smol}

\begin{lstlisting}[language=Rust]
async fn timeout_task<T, Fut>(duration: Duration, task: Fut) -> Option<T>
where
  T: Send + 'static,
  Fut: Future<Output = T> + Send + 'static,
{
  let mut handle = smol::spawn(task);
  let result = (&mut handle)
    .map(Some)
    .or(sleep(duration).map(|_| None))
    .await;
  if result.is_none() {
    handle.cancel().await;
  }
  result
}
\end{lstlisting}

\subsection{Semantics}\label{app:semantics}

This section completes the formal model of \Cref{sec:semantics}: definitions for all metafunctions and macros, followed by the grammar and reduction rules of each language, ordered by extension (\Cref{fig:langs:lineage}). Rules shown in the main-text figures are repeated so that each language's definition is self-contained. One additional notational convenience: $Q_0 \seqconcat (\ell, \kappa) \circ Q_1$ selects an entry at an arbitrary position of a queue, where $\seqconcat$ denotes queue concatenation; rules that match $(\ell, \kappa) \circ Q$ pop the queue head. We use the same notation for the signal queue $T$. Each grammar extension also extends the evaluation contexts pointwise into every argument position of its new forms; we omit those clauses.

\paragraph{The Task Struct}
A task is a struct of eight boxed fields; each field holds a pointer ($\mathsf{ptr}(x)$, as allocated by $\mathbfsf{ref}$) to a heap cell, so $!e.f$ reads and $e.f := e$ writes the underlying cell. A freshly allocated task is running, unawaited, uncancelled, with no relatives and no waiters:
$$
\begin{array}{l@{\ }l}
v_{\mathit{task}} = \mathbfsf{struct}\,\{
  & \mathit{self} = \mathsf{ptr}(x_{\mathit{task}}),
    \mathit{parents} = \mathsf{ptr}(x_{\mathit{pa}}),
    \mathit{children} = \mathsf{ptr}(x_{\mathit{ch}}),
    \mathit{status} = \mathsf{ptr}(x_{\mathit{st}}), \\
  & \mathit{value} = \mathsf{ptr}(x_{\mathit{va}}),
    \mathit{awaited} = \mathsf{ptr}(x_{\mathit{aw}}),
    \mathit{cancelled} = \mathsf{ptr}(x_{\mathit{ca}}),
    \mathit{waiters} = \mathsf{ptr}(x_{\mathit{wa}})\ \}
\end{array}
$$
The $\mathit{parents}$ cell holds the task's dependents (the tasks awaiting it) and $\mathit{children}$ its dependencies, both as lists of task pointers; $\mathit{waiters}$ holds a list of label--continuation pairs $(\ell, \kappa)$ as consumed by $\mathbfsf{sys\textbfsf{-}start\textbfsf{-}soon}$; $\mathit{status}$ ranges over $\textsf{``running''}$, $\textsf{``done''}$, and $\textsf{``failed''}$. Failure branches below throw $\textsf{``IME''}$ (internal model error); they are unreachable when the platform invariants hold.

\paragraph{Metafunction Definitions}
At the meta level we write $\sigma(x).f$ for the pointer stored in field $f$ of the task struct $\sigma(x)$, and $!_{\sigma}\, v.f$ for the cell contents $\sigma(x_f)$ where $v.f = \mathsf{ptr}(x_f)$.

\vspace{0.75em}
\noindent
$\begin{array}{@{}l@{}}
\mathsf{task\text{-}alloc}(\sigma_0) = (\sigma_1[x_{\mathit{task}} \mapsto v_{\mathit{task}}],\ x_{\mathit{task}}) \\
\quad \where\ x_{\mathit{task}}, x_{\mathit{pa}}, x_{\mathit{ch}}, x_{\mathit{st}}, x_{\mathit{va}}, x_{\mathit{aw}}, x_{\mathit{ca}}, x_{\mathit{wa}} = \many{\mathsf{gensym}()},~ v_{\mathit{task}}\ \text{as above} \\
\quad\qquad \sigma_1 = \sigma_0[x_{\mathit{pa}} \mapsto [\,],\ x_{\mathit{ch}} \mapsto [\,],\ x_{\mathit{st}} \mapsto \textsf{``running''},\ x_{\mathit{va}} \mapsto (), \\
\quad\qquad\qquad\quad\ \ x_{\mathit{aw}} \mapsto \mathbfsf{false},\ x_{\mathit{ca}} \mapsto \mathbfsf{false},\ x_{\mathit{wa}} \mapsto [\,]]
\end{array}$

\vspace{0.75em}
\noindent
$\begin{array}{@{}l@{}}
\mathsf{task\text{-}alloc\text{-}dependency}(\sigma, \sfid{sync}) = \mathsf{task\text{-}alloc}(\sigma) \\

\subsubsection{The Base Language \lc}\label{app:semantics:lc}

\subsubsection{The Async Platform \lasync}\label{app:semantics:platform}

The complete \lasync grammar extends the illustrative subset of \Cref{fig:lasync:grammar} with the $\mathbfsf{sys\textbfsf{-}block}$ and $\mathbfsf{sys\textbfsf{-}time}$ forms, the evaluation contexts $E$, and the machine configuration $C$:

$$
\begin{array}{l}
\begin{array}{rcl @{\hspace{3em}} rcl}
  \mathsf{Time}\ t              & \in  & \mathbb{N}_0 \cup \{\infty\}              & \mathsf{Frame}\ F         & ::= & \langle \ell, e \rangle \\
  \mathsf{Label}\ \ell          & ::=  & x \mid \mathbfsf{sync}                    & \mathsf{Frame\ Stack}\ FS & ::= & \epsilon \mid F \circ FS \\
  \mathsf{Continuation}\ \kappa & ::=  & \mathbfsf{fn}\ x_{\mathit{unit}} \to e   & \mathsf{Process}\ P       & ::= & \{ FS_1, \dots, FS_n \} \\
  \mathsf{Signal\ Queue}\ T     & ::=  & \epsilon \mid (t, \ell, \kappa) \circ T  & \mathsf{Task\ Queue}\ Q   & ::= & \epsilon \mid (\ell, \kappa) \circ Q \\
  \multicolumn{6}{c}{\mathsf{Config}\ C \ ::=\ \langle t, \sigma, Q, T, P \rangle}
\end{array} \\
\\
\begin{array}{rcl}
e & ::=  & \dots \mid \mathbfsf{sys\textbfsf{-}block}(e) \mid \mathbfsf{sys\textbfsf{-}time}() \mid \mathbfsf{sys\textbfsf{-}io}(e, e) \\
  & \mid & \mathbfsf{sys\textbfsf{-}start\textbfsf{-}soon}(\many{\ell,e}) \mid \mathbfsf{sys\textbfsf{-}start\textbfsf{-}later}(e, \ell, e) \\
E & ::=  & \dots \mid \mathbfsf{sys\textbfsf{-}block}(E) \mid \mathbfsf{sys\textbfsf{-}io}(E, e) \mid \mathbfsf{sys\textbfsf{-}io}(v, E) \mid \mathbfsf{sys\textbfsf{-}start\textbfsf{-}soon}(E) \\
  & \mid & \mathbfsf{sys\textbfsf{-}start\textbfsf{-}later}(E, \ell, e) \mid \mathbfsf{sys\textbfsf{-}start\textbfsf{-}later}(v, \ell, E)
\end{array}
\end{array}
$$

The platform is parameterized by two scheduling flags. Under \emph{serial dispatch} the rules \semrule{Sys-Schedule}, \semrule{Sys-Schedule-Cancelled}, and \semrule{Sys-Signal} carry the side conditions marked \textit{(serial dispatch only)}: queued work may be dispatched only when every thread is idle ($\mathsf{idle}(P)$), and a signal may fire only when, additionally, the task queue is drained ($Q = \epsilon$)---reproducing an event loop's run-to-completion, microtask-before-macrotask discipline. Under a \emph{single-threaded} instantiation the process $P$ holds a single frame stack and \semrule{Sync-Step} runs synchronous code to completion atomically. \Js{} is single-threaded with serial dispatch; Asyncio and Trio are single-threaded without serial dispatch; \CSharp{}, Swift, Tokio, and Smol are multithreaded.

\paragraph{Runtime Entry, Exit, and Collection}
\semrule{OS-Block-Done} is the platform's default exit rule: the root frame unblocks only at quiescence---both queues drained and all workers idle. Languages override it to exit earlier (\CSharp, Tokio, Smol) or to first cancel outstanding work (Asyncio, Trio). \semrule{Sys-GC} reclaims a heap binding referenced nowhere else; $\mathsf{fv}$ gives the names referenced by its arguments. The task queue $Q$ appears in the root set, so a queued task is always retained (\strong \references).

\subsubsection{Swift}

Swift extends \lasync over \exn, multithreaded. Its cancellation is cooperative: a $\mathsf{timeout}$ deadline only sets a flag, and because $\mathsf{task\text{-}cancelled}$ walks parents, an entire subtree observes an ancestor's flag. const std = @import("std");
const Io = std.Io;
const Allocator = std.mem.Allocator;
const assert = std.debug.assert;

fn producer(
    io: Io,
    queue: *Io.Queue([]const u8),
    flavor_text: []const u8,
) !void {
    try queue.putOne(io, flavor_text);
}

fn consumer(
    io: Io,
    queue: *Io.Queue([]const u8),
) ![]const u8 {
    return queue.getOne(io);
}

fn run_client_server(io: Io) !void {
    var queue: Io.Queue([]const u8) = .init(&.{});

    var producer_task = try io.concurrent(producer, .{
        io, &queue, "hello",
    });
    defer producer_task.cancel(io) catch {};

    var consumer_task = try io.concurrent(consumer, .{ io, &queue });
    defer _ = consumer_task.cancel(io) catch {};

    const result = try consumer_task.await(io);
    std.debug.print("msg received {s}\n", .{result});
}
