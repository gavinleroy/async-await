\subsubsection{Suspension}\label{ssec:designdims:suspension}

The Suspension axis defines if an await point is guaranteed to suspend. The possible values are: \textit{static,} and \textit{dynamic.}

\begin{figure}[H]
  \begin{minipage}[t]{0.49\textwidth}
\begin{lstlisting}[language=JavaScript]
async function print(msg) {
  console.log(msg);
}

async function work(name) {
  await print(name);
  await print(name);
  await print(name);
}

async function main() {
  let a = work("A");
  let b = work("B");
  await print("C")
  await a; await b
}

await main()
// => ABCABAB
\end{lstlisting}
    \cprotect\subcaption{}
    \label{fig:designdims:suspend:static}
  \end{minipage}\hfill%
  \begin{minipage}[t]{0.49\textwidth}
\begin{lstlisting}[language=Rust]
async fn print(msg: &str) {
  print!("{msg}");
}

async fn work(name: &str) {
  print(name).await;
  print(name).await;
  print(name).await;
}

fn main() {
  smol::block_on(async {
    let a = smol::spawn(work("A"));
    let b = smol::spawn(work("B"));
    print("C").await;
    a.await; b.await;
    drop(signal);
  });
} // => CAAABBB
\end{lstlisting}
    \cprotect\subcaption{}
    \label{fig:designdims:suspend:dynamic}
  \end{minipage}
  \caption{Examples of static and dynamic suspension.}
  \label{fig:designdims:suspend}
\end{figure}

\Cref{fig:designdims:suspend:static} provides a JavaScript program that demonstrates static suspension points. The provided program will always print ``ABCABAB.'' The first ``AB'' is a result of JavaScript's \textit{eager application}, see \Cref{ssec:designdims:eagerness}, the remaining interleaved prints are a result of static suspension points. At every \code{await} keyword, JavaScript will suspend the current \Task{} to provide another a chance to make progress. \footnote{This behavior is defined as part of the ECMAScript standard (\textsection 27.7.5.3, step 3.b)~\cite{ecma_ecmascript_nodate}.}

\Cref{fig:designdims:suspend:dynamic} provides a Smol (Rust) program that demonstrates dynamic suspension points. The provided program will always print ``CAAABBB'' --- none of the await expression suspend the current computation. Many languages opt for dynamic suspension points for performance reasons. If the awaited expression returns synchronously, then the executing thread has more work to do and can continue executing. Static suspension points may cause unnecessary overhead if the suspended task is immediately rescheduled.

When deciding between suspension strategies language designers make a trade off between starvation and performance. Asynchronous programming relies on \tasks to \textit{cooperatively} suspend in order for another to make progress. A static suspension policy ensures that a \task suspends exaxtly as many times as it was programmed to. The developer knows how many times an asynchronous function will suspend by counting the syntacticly-present await keywords.

A static suspension policy comes at the cost of performance and allocation. Many asynchronous function calls execute synchronously: and a \task could be suspended just to be immediately rescheduled. A dynamic suspension policy takes advantage of this by only paying the cost of suspension when a result is not ready. The downside to dynamic suspension is that a running \task might not suspend as often as a developer thinks. A common practice is to profile a system against a real-world workload and insert hard suspension points to force \tasks to suspend.
